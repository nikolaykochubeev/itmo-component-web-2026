# Тестирование React-компонентов

Локальная демонстрация к докладу на 20 минут для курса «Компонентное веб программирование 2026». Форма подписки иллюстрирует проверки поведения через React Testing Library и Vitest.

[Редактируемая презентация в Spaces](https://chatgpt.com/space/page_99e55cfea88c819196bdee5b44327443) содержит 15 слайдов и заметки докладчика с источниками. Полный текст для репетиции доступен в [SPEAKER-NOTES.md](SPEAKER-NOTES.md).

## Запуск

Нужен Node.js 22.12+ из ветки 22.x либо Node.js 24.x или 26.x. Проверено на Node.js 22.12.0. Нечётные ветки Node.js здесь не поддерживаются. Для установки нужен доступ к npm. После установки демонстрация работает без интернета.

```sh
cd /Users/nikolai/Projects/itmo-study/course-48/report-demo
npm ci
npm run dev
```

Откройте адрес из терминала, обычно `http://127.0.0.1:5173`. Vite занимает следующий порт, если 5173 уже занят.

```sh
npm test
npm run test:watch
npm run build
```

`npm test` завершает запуск и возвращает код ошибки при падении. `test:watch` перезапускает тесты при изменениях. `build` создаёт `dist/`.

## Что показывать

- Пустой или неверный адрес: связанная с полем ошибка, запрос не начинается.
- `reader@example.org`: кнопка и поле блокируются на 600 мс, затем появляется подтверждение.
- `error@example.org`: сервис имитирует отказ. Адрес можно исправить и отправить снова.
- Клавиатура: Tab переводит фокус в поле, Enter отправляет форму.

Сервис в `src/main.jsx` искусственный. Он не делает сетевых запросов, не создаёт реальную подписку и не хранит адреса. Простая проверка формата адреса нужна для учебного примера, а не для полной проверки RFC.

## Тесты

В `src/SubscribeForm.test.jsx` шесть сценариев:

1. Доступное имя поля и отправка клавиатурой.
2. Пустое значение и отсутствие вызова сохранения.
3. Неверный формат и отсутствие вызова сохранения.
4. Успех и передача адреса без пробелов в сервис.
5. Блокировка повторной отправки до завершения запроса.
6. Ошибка сервиса и успешная повторная попытка.

`subscribe` передаётся в компонент как зависимость. В тестах управляем только этой границей. Сам React-компонент, DOM и пользовательские действия остаются реальными. Проверка аргумента `subscribe` защищает контракт формы с сервисом, а проверка DOM подтверждает видимый результат.

`jsdom` моделирует DOM в Node.js. Эти тесты не проверяют расположение элементов, стили, реальную сеть и поведение всех браузеров. Для критического полного маршрута нужен отдельный браузерный тест.

## Live-сценарий

Пошаговый показ на 4 минуты находится в [LIVE-DEMO.md](LIVE-DEMO.md). Полный текст и тайминг доклада находятся в [SPEAKER-NOTES.md](SPEAKER-NOTES.md). Безопасный автоматический вариант:

```sh
npm run demo:red-green
```

Он проверяет исходный набор, временно убирает `disabled` у кнопки, подтверждает падение конкретного теста, восстанавливает исходный файл и снова запускает все тесты. Код восстанавливается в `finally`-эквиваленте и обработчиках обычного прерывания. Как и любой процесс, он не может обработать `SIGKILL` или отключение питания. Не редактируйте компонент одновременно с этим скриптом.
