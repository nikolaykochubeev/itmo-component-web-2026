# Live-демонстрация на 4 минуты

## Подготовка до доклада

1. Выполнить `npm ci`, `npm test`, `npm run build`.
2. В первом терминале выполнить `npm run dev`, открыть адрес из вывода Vite.
3. Во втором терминале перейти в папку demo. Открыть рядом `src/SubscribeForm.jsx` и `src/SubscribeForm.test.jsx`.
4. Увеличить шрифт терминала и редактора. Проверить, что зрители видят код и результаты тестов.
5. Убедиться, что файл компонента сохранён и никто не редактирует его параллельно со скриптом.

## 00:00–00:40. Сначала поведение

Показать форму. Отправить пустое значение. Ввести `reader@example.org`, отправить и заметить короткое состояние «Сохраняем…».

Реплика: «У формы небольшой контракт: она объясняет ошибку ввода, показывает ожидание, сообщает результат и позволяет повторить попытку. Именно это мы будем проверять».

## 00:40–01:25. Успех и ожидание в коде

Открыть тест «после сохранения показывает адрес без пробелов». Пройти по строкам: `userEvent.setup()`, `render`, поиск `textbox`, ввод, клик, `findByRole('status')`, видимое подтверждение и нормализованный аргумент сервиса.

Реплика: «Тест находит элементы по тому, как их представляет интерфейс. `findByRole` ждёт появления результата. Нам не нужен произвольный таймер на одну секунду».

Затем открыть тест «блокирует повторную отправку до завершения запроса». Показать незавершённый Promise. До `resolveRequest()` тест видит кнопку ожидания и отсутствие успешного результата. После завершения получает подтверждение.

Реплика: «Скорость сети не управляет тестом. Мы сами выбираем момент, когда зависимость заканчивает работу, и проверяем промежуточное состояние».

## 01:25–03:25. Тест обнаруживает регрессию

Выполнить:

```sh
npm run demo:red-green
```

Скрипт сначала покажет шесть успешных тестов. Затем удалит только `disabled` у кнопки. Тест блокировки упадёт с сообщением `toBeDisabled`. Скрипт восстановит файл и снова покажет шесть успешных тестов.

Реплика: «Это намеренная регрессия. Красный результат показывает, какую ошибку ловит конкретная проверка. После восстановления получаем зелёный набор. Защита в обработчике остаётся, а тест дополнительно защищает состояние самой кнопки».

## 03:25–04:00. Дополнительная защита и граница примера

Показать `if (isSaving) return` в обработчике. Он дополнительно защищает от повторного запроса. Мутация демонстрирует ошибку в состоянии самой кнопки. Затем коротко указать на тест ошибки и повторной попытки: компонент получает искусственную функцию `subscribe`.

Реплика: «Эти проверки быстро защищают контракт компонента. Реальное API, браузер и полный маршрут пользователя потребуют отдельной проверки на другом уровне».

## Запасной вариант

Если проектор или браузер не запускается, показать код тестов и выполнить `npm run demo:red-green` в терминале. После первоначальной установки пакетов интернет для показа не нужен. Если общий live-показ затягивается, достаточно одного теста успеха и одного красного теста блокировки.

Для ручного показа вместо скрипта запустить `npm run test:watch`, удалить `disabled={isSaving}` только у `<button>`, увидеть падение и сразу вернуть атрибут. Перед завершением выполнить `npm test`.
